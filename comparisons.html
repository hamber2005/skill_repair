为什么会出现这个差异

直接证据最合理的解释当前不能推出
WML 的修改、执行回读和 verifier 结果构成完整闭环；MMG2Skill 的新增规则与失败断言在语义上直接相反。SkillGrad 与 SkillRevise 最终也留下同一个 End 节点错误。本题的关键是一条无歧义的终止节点约定；更长的通用检查清单没有覆盖这条规则。WML 与 SkillAxe 把禁止条件直接写进 Skill，执行产物也遵守；MMG2Skill 写反了规则，SkillGrad 则把修复重点放在交付检查上。Opus 原始 Skill 在另一次运行中已通过，因此这里能解释这些 GPT 运行的差异，不能据此断言某种方法在重复运行中必然胜出。
案例 02 · 电力市场出清与定价

案例二：成本只越过容差 9.5 美元，根因仍是模型契约用错

SkillAxe 与 MMG2Skill 都算到约 296.533 万美元，看起来很接近；但它们擅自启用了 tap 与 phase shift 扩展模型。通过方法保持任务要求的简化 DC 方程 b=1/X，成本与参考值吻合。

为什么会出现这个差异

直接证据最合理的解释当前不能推出
两种失败方法得到几乎相同的低成本，并都在代码中读取 tap/shift；两种通过方法都使用 b=1/X 的简化模型。人工 Gold D001 也明确要求不得因输入含 tap/shift 列而改换物理模型。这是“结果很接近，但问题仍是离散契约错误”的典型例子。继续调 solver 容差可能掩盖症状，真正需要固定的是任务采用哪套 DC 方程。模型契约一旦错了，数值再稳定也会稳定地算出另一道题。求解器和后处理也存在差异；当前证据最强地支持模型契约与结果偏差一致，尚未对 tap/shift 单因素做受控消融。

为什么会出现这个差异

直接证据最合理的解释当前不能推出
分项 F1 能直接看到 WML 的指标交换；SkillTTA 的执行轨迹记录了幅值和零填充列处理；MMG2Skill 与 SkillRevise 的脚本原文则保留了固定相位间隔。只优化模型权重没有同时控制数据映射、幅值、阈值和输出数量，容易把错误从一个相位转移到另一个相位。覆盖数据细节的方法在本次运行中通过；但依赖固定相位先验也能在当前数据上过线，因此任务 reward 不能替代对 Skill 内容的验收。各方法的模型、provider、候选数量和脚本均不同，不能把 F1 差异全部归因于某一句 Skill。固定延时在本题上造成多少收益或损失，也没有单独消融。
这三个案例共同说明：有效修复必须把具体规则写对，并让该规则进入实际执行；只看 reward 会漏掉“差一点”“修一项坏一项”以及“通过但违反 Gold”的差别。
